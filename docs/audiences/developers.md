# Developers & Engineering Teams

AgentFlyer fits engineering teams that need an Agent runtime with clear boundaries, not a one-off chat wrapper.

## Typical scenarios

- Build internal multi-agent workflows with coordinator and specialist roles.
- Reuse one runtime core across Web, CLI, and messaging channels.
- Add external tools through MCP with policy controls instead of ad hoc scripts.

## What success looks like

- Runtime behavior is observable from Console UI and CLI.
- Workflows are repeatable and schedulable.
- Sessions, memory, and deliverables remain durable and recoverable.
- Tool execution is bounded by approvals and sandbox profiles.
