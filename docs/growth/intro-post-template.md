## Post skeleton

### 1) Why we built this

Most agent projects become hard to operate once workflows, approvals, memory, and multi-channel delivery are required. We wanted one runtime to handle those concerns together.

### 2) What problem it solves

- Fragmented tooling across chat, workflow, scheduling, and delivery
- Weak operator visibility into execution and approval state
- Lack of durable outputs beyond one-off chat turns

### 3) Who it is for

- Builders and teams running repeatable agent workflows
- Operators needing approvals, sessions, scheduler, and deliverables
- Projects planning to evolve from single-host to cross-host collaboration

### 4) What you can run today

- Multi-agent runtime
- Workflow + scheduler
- MCP + sandboxed execution
- Console UI + CLI + multi-channel adapters
