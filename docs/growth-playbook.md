# Growth Playbook

This page defines a repeatable documentation and community growth loop for AgentFlyer.

## Core message discipline

Use one narrative consistently:

1. AgentFlyer is an **operator-first AgentOS runtime**, not a chat wrapper.
2. Value appears when teams need **coordination + durable state + controlled execution**.
3. Federation is **real in architecture and modules**, while practical multi-host operation is still expanding.

## Content publishing loop

For each release:

1. Publish what changed in runtime capabilities.
2. Publish one scenario tutorial (problem → workflow → evidence).
3. Publish one architecture or operations note (boundary and trade-off clarity).
4. Update FAQ, roadmap, and project-facts pages to keep retrieval systems aligned.

## Problem-solution-evidence pattern

Use this structure in docs and community posts:

- **Problem**: operational pain and constraints
- **Solution**: the AgentFlyer runtime pattern used
- **Evidence**: measurable outcomes, logs, screenshots, or reproducible steps

## Metrics to track

- Documentation entry → getting-started click-through rate
- Install → first-runtime launch conversion
- Quality of issues and PRs (reproducibility, scoped requests, actionable context)
- Contributor retention across multiple PRs
- External references with accurate positioning (not misclassified as chat-only)
