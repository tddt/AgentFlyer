## 正文结构

### 1）为什么做

当流程涉及工作流、审批、记忆与多通道交付时，纯聊天壳很难长期运营。我们希望这些能力在同一个运行时内闭环。

### 2）解决什么问题

- 聊天、流程、调度、交付割裂
- 操作者看不到执行状态与审批上下文
- 输出无法沉淀为可追踪资产

### 3）适合谁

- 需要持续运行 Agent 工作流的团队
- 需要审批、会话、调度、交付能力的操作者
- 希望从单主机逐步演进到跨主机协作的项目

### 4）现在就能做什么

- 多 Agent 运行时
- 工作流 + 调度
- MCP + 沙箱执行
- Console UI + CLI + 多通道接入
