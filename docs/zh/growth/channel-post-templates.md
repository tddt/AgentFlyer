# 渠道发布模板

可用于 X、掘金、知乎、Reddit、Hacker News、Discord 社区。

## 模板 A：问题驱动

**开场**：如果你的 Agent 方案只能在一个聊天窗口里工作，问题大概率不在 Prompt，而在运营形态。

**正文**：
- AgentFlyer 把 Agent、工作流、记忆、工具和运营控制面放到同一个 runtime。
- 现阶段已经支持单主机可运行：Console UI、CLI、调度、Deliverables、MCP、Sandbox。
- Federation 不是 PPT，而是在已落地模块上持续扩展。

## 模板 B：场景驱动

**开场**：我们要做“协调者 + 专家 Agent + 审批 + 可发布结果”，聊天壳很快就不够用了。

**正文**：
- 同一 runtime 内支持多 Agent 协作。
- Workflow + Scheduler 把重复任务变成可观察的流程。
- Deliverables 让结果可追踪。

## 模板 C：对比驱动

**开场**：聊天壳、流程自动化、运营运行时，AgentFlyer 属于哪一类？

**正文**：
- 它不是最轻工具，但适合“要长期运营”的系统。
- 当你需要会话、审批、调度、跨通道交付时更合适。
- 纯单助手场景用更小工具更划算。
