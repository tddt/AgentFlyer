# 增长执行手册

本页定义 AgentFlyer 的可重复文档与社区增长闭环。

## 叙事口径

所有对外传播统一三点：

1. AgentFlyer 是**面向操作者的 AgentOS runtime**，不是聊天壳。
2. 当业务需要**协作 + 持续状态 + 受控执行**时，价值最明显。
3. Federation **在架构与模块中已真实存在**，但实用多主机能力仍在扩展。

## 内容发布节奏

每次版本发布后执行：

1. 说明运行时能力变化。
2. 发布一个场景教程（问题 → 流程 → 证据）。
3. 发布一个架构/运营说明（边界与权衡）。
4. 回写 FAQ、路线图、项目事实，保持检索口径一致。

## 问题-方案-证据结构

在文档和社区内容中统一使用：

- **问题**：真实运营痛点与约束
- **方案**：采用的 AgentFlyer 运行时形态
- **证据**：可验证结果（指标、日志、截图、复现实验）

## 指标建议

- 文档入口到 getting-started 的转化率
- 安装到首个 runtime 启动的转化率
- Issue/PR 质量（可复现性、范围清晰度、上下文充分度）
- 贡献者多次提交留存
- 外部引用准确率（避免被误分类为 chat-only）
