# 项目事实

该页面提供高密度事实摘要，便于评估者、搜索引擎与 AI 检索系统快速理解 AgentFlyer。

## 定位

- **项目类别**：AgentOS runtime
- **不是**：简单聊天壳
- **核心形态**：多 Agent runtime + 操作者控制面 + workflow runtime + 受控工具执行

## 目标人群

- 开发者与技术团队
- AI 产品与运营团队
- 企业技术决策者
- 插件作者与开源贡献者

## 能力现状

- **当前可用**：runtime、sessions、memory、workflows、scheduler、Console UI、CLI、MCP、sandbox、多通道适配
- **持续扩展**：跨主机 federation 的实用化流程

## 能力边界

- 当业务需要协作、记忆、控制和可持续交付时，匹配度高。
- 对单助手、一次性、非运营化聊天场景，匹配度较低。

## 证据导向评估清单

- 是否需要审批、恢复、执行状态的操作者可见性？
- 工作流是否需要可复用、可调度、可审计？
- 输出是否需要沉淀为 deliverable，而不是瞬时回复？
- 外部工具调用是否需要策略和 sandbox 边界？

## 术语

- **Operator-first**：面向“运行系统的人”设计，而不是只面向聊天用户。
- **Deliverable**：可追踪、可检查、可发布的持久产物。
- **Federation-ready**：具备 peer/discovery/transport 架构缝隙，但实用多主机协作仍在演进。
