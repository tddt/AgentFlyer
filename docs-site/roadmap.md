# Roadmap

AgentFlyer already has a usable runtime surface. The roadmap is about deepening the system, not inventing it from scratch.

## What is already real

- multi-agent runtime
- workflows and scheduler
- memory and deliverables
- Console UI and CLI
- MCP integration and sandbox execution
- multi-channel entry points

## Next priorities

## Federation from seam to practice

Turn the current federation-oriented modules into more practical multi-host workflows, peer coordination, and state movement that operators can use without hand-assembling infrastructure glue.

## MCP lifecycle hardening

Improve transport reliability, reconnect behavior, server lifecycle handling, and operator visibility so MCP integrations feel first-class in long-running environments.

## Safer execution defaults

Keep tightening sandbox policies, approval flows, and runtime controls so tool use remains observable and bounded as the system grows.

## Workflow depth

Push further on super-node coordination, structured review flows, and deliverable-driven operator processes so the runtime handles more real operational sequences natively.

## Lower operational token cost

Continue reducing avoidable token overhead while improving coordination quality, reuse of runtime state, and recovery from suspended or interrupted work.

## Design principle for future work

Every roadmap item should strengthen one of these properties:

- clearer operator control
- stronger runtime boundaries
- better repeatability and durability
- cleaner path from one host to many hosts

If a feature does not improve one of those, it probably does not belong near the center of the project.
